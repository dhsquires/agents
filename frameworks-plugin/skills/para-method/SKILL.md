# PARA Method

> Organize every piece of digital information across every tool into four buckets, sorted by how close it is to action.

**Author:** Tiago Forte, founder of Forte Labs
**Source:** *Building a Second Brain* (Atria Books, 2022); *The PARA Method* (Atria Books, 2023)
**Field-tested:** "Building a Second Brain" cohort (100,000+ alumni); used across Notion, Obsidian, Roam, Evernote

## When to use this
- Setting up or cleaning up a note-taking or knowledge system
- Files and notes are scattered and you can't find anything
- Standardizing structure across multiple tools (notes, tasks, cloud storage, email)
- Doing a weekly review and deciding what to archive
- Onboarding a new tool and wanting a consistent organizing scheme

## The framework
| Category | Definition |
|----------|------------|
| **Projects** | Short-term efforts with a defined endpoint, currently active |
| **Areas** | Ongoing responsibilities with no end date (health, finance, career, relationships) |
| **Resources** | Reference materials supporting projects and areas (topics of interest) |
| **Archives** | Inactive items from the other three categories (completed, paused, deprecated) |

**CODE companion:** Capture → Organize (into PARA) → Distill (progressive summarization) → Express (use it in your work)

## How to run it (step by step)
1. Apply PARA in every tool you use (notes app, task manager, cloud storage, email)
2. Move files *as close to action as possible* — if it's not actionable, it's Resources or Archives
3. Weekly review: move completed projects to Archive; promote relevant resources into active project folders

## Facilitating with the user
When this skill activates, you (Claude) should:
1. Restate or gather the user's context (current projects, ongoing responsibilities, tools in use)
2. Walk through each step of the framework sequentially, applied to their situation
3. Make any filled-in gaps explicit and labeled as assumptions
4. Flag the step where the analysis is weakest or you lack data (e.g., ambiguous Project vs Area calls)
5. Suggest 1-2 complementary frameworks for a second pass (e.g., OKRs to anchor Areas to goals)

## Output template
- **Projects:** <active efforts with defined endpoints>
- **Areas:** <ongoing responsibilities>
- **Resources:** <reference topics>
- **Archives:** <items to move out of active view>
- **Immediate actions:** 3 things to archive now, 3 resources to promote to active projects

## Watch out for
- Over-categorizing — when unsure between Project and Area, ask "is there an endpoint?"
- Letting Resources become a junk drawer; only keep what supports actual projects/areas
- Building elaborate structure instead of moving items closer to action
- Skipping the weekly review, which keeps the system from rotting
