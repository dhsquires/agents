# Recognition-Primed Decision Model (RPD)

> Experts don't compare options — they pattern-match the situation, simulate the first plausible action, and act.

**Author:** Gary Klein, cognitive psychologist; founder of Klein Associates (now KA LLC)
**Source:** *Sources of Power: How People Make Decisions* (MIT Press, 1998); developed 1985 with Calderwood and Clinton-Cirocco
**Field-tested:** Firefighting commanders, military officers (US Marines revised decision training based on RPD), ICU nurses, chess grandmasters

## When to use this
- A time-pressured decision in a domain where you have real experience
- No time to enumerate and compare every option
- Leveraging expert intuition rather than exhaustive analysis
- High-validity environments with consistent cause-effect relationships
- Stress-testing a gut call before committing

## The framework
Experienced practitioners pattern-match the situation to a type they've seen before, mentally simulate the first plausible course of action, check if it works, adjust if not, and act. Three phases:
1. **Situation recognition** — Does this match a pattern I know? What type of situation is this?
2. **Serial evaluation** — Simulate the first plausible option. Does it hold up?
3. **Action** — Implement the first option that passes simulation

**When it works:** High-validity environments (consistent cause-effect) plus adequate practitioner experience.

## How to run it (step by step)
1. When facing a time-pressured decision, ask: "What type of situation is this?"
2. Identify the first plausible course of action your pattern library produces
3. Mentally simulate it: "Walk forward — what happens?"
4. If it fails simulation, modify; if it passes, act

## Facilitating with the user
When this skill activates, you (Claude) should:
1. Restate or gather the user's context (the decision, their experience level, the domain's predictability)
2. Walk through recognition, serial evaluation, and action sequentially
3. Make any filled-in gaps explicit and labeled as assumptions
4. Flag the step where the analysis is weakest or you lack data
5. Suggest 1-2 complementary frameworks for a second pass

## Output template
- **Situation type:** what domain/pattern this resembles
- **First plausible action:** what an experienced practitioner would recognize
- **Mental simulation:** what could go wrong if you run it forward
- **Adjustment or go:** modified action, or crisp action plan if it passes

## Watch out for
- Using RPD in low-validity environments where patterns mislead
- Mistaking confident pattern-matching for genuine experience
- Skipping the mental simulation and acting on the first instinct
- Failing to adjust when the simulation reveals a flaw
